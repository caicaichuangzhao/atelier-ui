# 反馈：每一步都有回应

「尽量让用户操作时每一步都有反馈」（西瓜同学的设计主张）。落到工程上，每个交互拆成四拍，每一拍都要设计。

## 1. 四拍

| 拍 | 什么时候 | 做什么 | 数字 |
|---|---|---|---|
| 0 靠近（仅鼠标） | 指针进入 | 轻微抬起、磁吸、亮边、提示气泡 | 120–180ms；提示延迟 300–500ms |
| 1 按下 | pointerdown | 缩小、变深、阴影收紧 | <100ms 出现；scale 0.96–0.98 |
| 2 过程 | 拖动中 / 等待中 | 拖动：1:1 跟手，实时读出数值。等待：转圈、进度、阶段文字 | 300ms 内完成的不显示加载；转圈一旦出现至少 500ms；超过 2s 加阶段文字；超过 10s 给取消 |
| 3 结果 | 成功或失败 | 成功：对勾描出来，重要的再加一次小迸发。失败：横向抖 2–3 下、变危险色、写清原因和办法、给重试，保留用户输入 | 抖动 300–400ms |
| 4 归位 | 结果之后 | 回到可再次操作的状态；焦点回到触发处；刚改过的内容淡淡高亮一下再褪掉 | 成功约 1.5s 后复原，失败约 2.6s 或下一次输入时复原 |

- 可撤销的操作（删除、归档、移出）**优先给撤销**，不弹确认框。确认框只给不可撤销的。
- 频繁的操作反馈要安静，罕见又有意义的操作才值得庆祝。勾一个待办可以迸一下；保存草稿只需要一个状态字。
- iOS Safari 上 `:active` 默认不触发，给页面挂一个空的 `touchstart` 监听，或者用 JS 加 `.is-pressed`。

## 2. 状态矩阵（每个可交互元素都过一遍）

| 状态 | 视觉 | 可访问性 |
|---|---|---|
| 默认 | — | 有可读名字（文字或 `aria-label`） |
| 悬停 | 包在 `@media (hover: hover)` 里，触屏点完不会卡在悬停样式 | — |
| 聚焦 | `:focus-visible` 焦点环，瞬间出现 | Tab 顺序合理 |
| 按下 | <100ms | — |
| 选中 / 展开 | 不只靠颜色：加对勾、填充图标或位移 | `aria-pressed` / `aria-selected` / `aria-expanded` |
| 加载 | 保留原宽度，不让布局跳 | `aria-busy="true"`；结果用 `aria-live` 播报 |
| 成功 | 对勾、颜色、文字 | `role="status"` 播报 |
| 错误 | 图标 + 文字 + 颜色；保留输入 | `aria-invalid`，`aria-describedby` 指向错误文字 |
| 禁用 | 透明度 0.4–0.5，`cursor: not-allowed` | 尽量用 `aria-disabled` 而不是 `disabled`，元素还能聚焦，可以说明原因 |
| 空 | 一句说明 + 一个下一步按钮 + 一个示例预览 | — |

**禁用的按钮要说清为什么不能点**：悬停或聚焦时提示「先填写邮箱」。只把按钮变灰，用户只能猜。

## 3. 手势：过线才算数

揭角、下拉、长按、滑动删除这类「拖过一条线才生效」的手势：

1. **预演**：手势进行中就让用户看到会发生什么。贴纸翘起、绳子拉长、进度环在填。
2. **过线信号**：越过阈值那一刻给一个明确变化：颜色变、轻震一下、提示「松手即切换」。
3. **反悔**：没过线松手就弹回；过了线又退回来，信号也要撤回。
4. **键盘等价**：每个手势都有按键替代（回车揭开、空格长按），手势不能是唯一入口。

连续输入（滑块、滚轮、分段）：实时显示当前值，每跨一格轻震一下，预览效果立即生效，松手后吸附到最近的一格。

## 4. 系统反馈

- **乐观更新**：先改界面再等服务器；失败就回滚，并用 toast 说明「没保存上，已恢复」。
- **骨架屏**：内容区加载用骨架屏，形状和真实内容一致；按钮触发的操作用按钮内转圈，不盖全屏遮罩。
- **多阶段**：上传 → 处理 → 完成，每个阶段都显示出来，用户知道卡在哪一步。
- **列表变化**：新项从它的来源方向进来，删除的项先收起高度再消失，旁边的项平滑补位，不跳。
- **复制**：图标变成对勾约 1.2s，同时播报「已复制」。`Atelier.copy()` 在 file:// 和 http 页面也能用。
- **toast** 是播报，不是确认。重要的结果写在页面上原地显示，toast 只做补充。

## 5. 触屏重排

触屏没有「靠近」这一拍。照搬鼠标版的步骤，会出现永远不会发生的悬停步骤。

- 把四拍重排成：按下 → 过程 → 结果 → 复位。示例页用 `data-steps="靠近|按下|处理中|结果"` 和 `data-steps-touch="按下|处理中|结果|复位"` 两套标签，按 `Atelier.fine` 切换。
- 只在悬停时出现的信息（提示气泡、悬停才显示的操作按钮），触屏上改成点按出现或常显。
- 右键菜单在触屏上用长按（约 500ms），并且菜单里的操作在别处也能找到。

## 6. 反馈强度跟风格走

同一个「完成」：
- **墨 Ink**：对勾描出，文字加删除线并变淡，没有迸发。
- **夜航 Night**：对勾描出 + 一圈主色辉光，200ms 内褪掉。
- **团子 Dango**：方框弹一下（bouncy），彩色纸屑迸开，计数跳 +1。
- **瓷 Porcelain**：对勾描出，卡片阴影轻轻收一下，几乎无声。

## 7. 可访问性

- 异步结果都要播报：`role="status"` 或 `aria-live="polite"`。`Atelier.toast()` 用的就是一个 polite 的播报区。
- 每个状态不靠颜色也能分清：图标、文字、形状至少一样。
- 减少动态时，反馈保留，只是去掉运动：对勾直接出现，抖动换成颜色和文字。
- 声音默认关；轻震只在有意义的阈值触发一次，不跟着每一帧震。

## 8. 交付前自查

- [ ] 每个可交互元素按下都有 <100ms 的变化
- [ ] 加载不闪（<300ms 不出转圈，出了至少 500ms）
- [ ] 错误写了原因和办法，用户输入还在
- [ ] 成功之后会自己复原，或者有明确的下一步
- [ ] 手势有过线信号、能反悔、有键盘替代
- [ ] 触屏上没有只靠悬停才能拿到的东西
- [ ] 读屏能听到结果；状态不只靠颜色
