# 配色：从旋钮推导，不从模板挑

## 1. 为什么用 OKLCH

OKLCH 的 L（亮度）接近人眼感受：L 相同的两个颜色看起来一样亮。所以可以先定亮度和彩度，再自由换色相，对比度不会崩。`assets/palette.js` 在 OKLCH 里设计，压进 sRGB 输出 hex，并自动检查对比度。

## 2. 用脚本推导（首选）

```bash
node scripts/palette.mjs --accent 32 --neutral 70 --tint 0.014 --chroma 0.17 --spice 262
node scripts/palette.mjs --brand "#4f46e5" --neutral 270 --tint 0.008
node scripts/palette.mjs --neutral 255 --tint 0.012 --accent 125 --chroma 0.19 --mode dark --json
node scripts/palette.mjs --accent 262 --neutral 250 --tint 0.006 --preview palette.html
```

- 输出两段 CSS（浅色 `:root`、深色 `[data-mode="dark"]`），每段开头是对比度报告和警告。`--dark-selector media` 改成 `prefers-color-scheme`。
- `--brand "#hex"`：已有品牌色时用它。浅色模式主色就是这个 hex；深色模式同色相，亮度自己选。品牌色接近灰色时会提示手动给 `--neutral`。
- 任何旋钮前加 `light-` 或 `dark-` 只改一个模式，比如 `--dark-tint 0.012`。
- `--preview` 生成色板页（正文、按钮、标签、状态点、柱状图、对比度表），用 qa.py 截图看效果。
- 退出码 1 = 必需的对比度没过：按警告改对应旋钮再跑。退出码 2 = 参数错误。
- 浏览器里实时推导：`AtelierPalette.apply(document.documentElement, { mode, accentHue, neutralHue, tint, chroma, ... })`，返回 `{ tokens, report, warnings }`。

不能运行脚本时：用第 3 节的旋钮值手写 `oklch()`，再按第 5 节的门槛逐对估算对比度，并在交付里注明「对比度未经脚本验证」。

## 3. 旋钮怎么选

| 旋钮 | 范围 | 怎么定 |
|---|---|---|
| `--neutral` 中性色相 | 暖纸 50–90，中性 ~100，冷石墨 230–270 | 跟温度旋钮走；通常与主色同侧或互补 |
| `--tint` 中性彩度 | 0 纯灰，0.006 若有若无，0.014 看得出暖/冷，0.02 明显带色 | 温度 1 或 5 才用到 0.014 以上；深色模式常比浅色高 0.002–0.004 |
| `--accent` 主色色相 | 0–360 | 从产品隐喻里找：墨与朱砂 ~32，荧光笔 ~125，青瓷 ~178，钴蓝 ~262，樱花 ~355。避开默认的「AI 紫蓝」260–290，除非品牌就是它 |
| `--chroma` 主色彩度 | 0.08 低调，0.15 默认，0.19 鲜明，0.22 很响 | 跟能量旋钮走；高亮度主色（L>0.78）彩度别超过 0.18，否则发荧光 |
| `--accent-l` 主色亮度 | 0–1 | 通常不用填。糖果色、荧光色才手动提高到 0.74–0.88，脚本会自动配深色文字 |
| `--spice` 点缀色 | 色相 + `--spice-chroma` | 只在能量 ≥4 时加；只用于标签、插画、图表强调，不做按钮 |

## 4. Token 角色（组件只认这些名字）

| Token | 用在 | 别用在 |
|---|---|---|
| `bg` / `surface` / `sunken` | 页面底 / 卡片和浮层 / 凹陷区（输入框、代码块） | 不要在 surface 上再叠一层同色 surface |
| `line` / `line-strong` | 分割线、卡片描边 / 输入框边框、强调分隔 | 文字 |
| `text` / `text-2` / `text-3` | 正文和标题 / 次要说明 / 时间、注释、占位 | text-3 不写正文段落 |
| `accent` | 主按钮底色、选中态、进度条 | 大段文字、整块背景 |
| `accent-hover` / `accent-strong` | 主按钮悬停 / 背景上的强调文字、链接、图标 | — |
| `accent-ink` | 压在 accent 上的文字和图标 | — |
| `spice` | 第二点缀：标签描边、插画、图表重点 | 主操作 |
| `ok` / `warn` / `bad` / `info` | 状态：一定配图标或文字 | 装饰 |
| `data-1` … `data-6` | 图表系列，亮度一致、色相拉开 | 状态 |
| `shadow-c` | 阴影色（带中性色相） | — |

派生色在 tokens.css 里用 `color-mix()` 生成：`--c-accent-soft`（主色淡底，选中行、标签底）、`--c-accent-wash`（更淡，区块底）、`--c-hover` / `--c-press`（悬停和按下的叠色）。浅色和深色都会自动跟着走。

## 5. 对比度门槛（脚本会检查）

| 一对颜色 | 最低 | 级别 |
|---|---|---|
| text / bg | 7:1 | 必需 |
| text-2 / bg | 4.5:1 | 必需 |
| text-3 / surface | 4.5:1 | 必需 |
| accent-ink / accent | 4.5:1 | 必需 |
| accent-strong / bg | 4.5:1 | 必需 |
| accent / bg（图标、边框） | 3:1 | 建议；不够就用 accent-strong 画图标和边框 |

## 6. 用色规则

1. **面积**：中性色约 85–90%，主色 5–10%，点缀色和状态色合起来不超过 5%。
2. **状态不只靠颜色**：错误 = 红色 + 图标 + 一句原因。色弱用户和黑白打印都要看得懂。
3. **渐变**写 `linear-gradient(in oklch, …)`，两端色相差别超过 60°，中间容易出现脏灰或意外的第三种颜色。
4. **深色模式不是反色**：越高的层越亮（bg < surface < 浮层）；阴影几乎看不见，改用顶部亮边 `--hl-inset`；大面积彩色降彩度。纯黑 `#000` 只在 OLED 省电是明确目标时用。
5. **换主题只换 token**，不改组件 CSS。
6. **图表**按 data-1、data-2… 顺序取色；超过 6 个系列先合并成「其他」，或者改用直接标注。

## 7. 常见错误

| 错误 | 为什么错 | 改成 |
|---|---|---|
| 白底上用 `#999` 写说明 | 2.85:1，看不清 | 用 text-3；纯灰起码 `#767676`（4.54:1） |
| 亮绿、亮橙按钮配白字 | `#22c55e` 配白字只有 2.28:1，`#f97316` 只有 2.80:1 | 让脚本配 accent-ink（深色字），或降低主色亮度 |
| 主色到处用：标题、图标、边框、背景 | 没有重点，显得廉价 | 主色只给主操作和选中态 |
| 纯灰中性色 + 一个饱和蓝 | 「默认后台」的味道 | 中性色带 0.006–0.014 的色相 |
| 状态色随手挑 | 亮度不一，红的刺眼、黄的看不清 | 用脚本给的 ok/warn/bad/info |
| 深色模式直接反色 | 层级颠倒，阴影发脏 | 用 `--mode dark` 重新推导 |
| 从参考图吸管取色 | 截图压缩、显示器偏色，对比度不保证 | 估出色相后交给脚本推导 |
