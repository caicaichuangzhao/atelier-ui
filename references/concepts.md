# 概念放大：把一句话的想法做成有创意的组件

用户描述组件时往往只说一句：「i 按钮点了变成胶囊」「长按确认」「拉一下切换主题」。不要照字面做个最朴素的版本，也不要换成你自己的点子。按下面六步，在用户的概念上做加法。

## 1. 六步

1. **听意图**：用户真正想要的感觉是什么？「i 按钮变胶囊」的意图是：信息就在手边，不跳出当前语境，用完就收。
2. **找隐喻**：在现实世界里，什么东西会这样动？隐喻免费送你一套运动规则：质量、阻力、方向、声音。胶囊从按钮里「长出来」，所以它的左边缘不动，向右伸展；印章要「蓄力再落下」，所以按住时下沉、松手时砸下并回弹。
3. **拆步骤**：把这个动作拆成 3–5 拍（见 feedback.md 的四拍），每一拍各配一个反馈。
4. **定约束**：尺寸（鼠标 32px，触屏 44px）、边界（离容器边缘 16px 截断）、同时只开一个、Esc 和点外面关闭、减少动态时怎么办、读屏读什么、键盘怎么操作。
5. **加一个惊喜**：只加一个，代价低，不拖慢操作。比如 i 在展开时转一圈变成实心；印章落下时纸面轻震一下。
6. **写成规格再做**：附动效说明表（motion.md 第 10 节）+ 状态表 + 一句理由。做完在桌面和触屏上各试一遍。

**忠于原意**：用户点名的核心动作不能改。用户说「按钮本身变成胶囊」，就不能换成「按钮旁边弹出一个浮层」。改进都是在原动作上加东西。真有更好的方向，单独列为「可选方案」，默认交付仍按用户的版本。

## 2. 实例：信息胶囊（examples/showcase 的 c-pill）

| 用户说的 | 放大后的规格 |
|---|---|
| 「一个 i 按钮」 | 圆形，鼠标下 32px，触屏 44px（`--ipill-size` 可改） |
| （没说悬停） | 悬停时右侧出现带小三角的提示气泡，告诉用户点了会怎样 |
| 「点了变成胶囊」 | 按钮本身向右长成胶囊，不是另开一层；左边缘不动，像从按钮里长出来 |
| （没说多宽） | 宽度 = 按钮 + 内容的自然宽度；离容器右边缘 16px 处截断成省略号 |
| 「显示信息」 | 内容从左往右揭开（`clip-path`），比外壳晚一点到位 |
| （惊喜） | i 转一圈变成实心，并发出一圈光晕 |
| （没说复制） | 末端带复制按钮，成功后图标变对勾，播报「已复制」 |
| （没说关闭） | 同时只展开一个；Esc 或点外面收回成圆；`aria-expanded` 同步 |
| （没说触屏） | 触屏没有悬停：轻点直接展开，步骤标签换成「轻点 / 展开 / 复制 / 收起」 |

## 3. 隐喻表（起点，不是答案）

| 想法 | 隐喻 | 借来的运动规则 | 关键反馈 |
|---|---|---|---|
| 长按确认 | 盖章 | 蓄力时下沉；落下有加速度和回弹 | 进度环、提前松手倒回、落印轻震 |
| 切换深浅色 | 拉灯绳 | 越拉阻力越大；松手带摆动弹回 | 过线锁定、从拉绳处扩散的转场 |
| 揭晓奖励 | 揭贴纸 | 折痕是角点与指尖连线的垂直平分线 | 过半可撕、没过半贴回 |
| 选金额 | 滚轮 / 老虎机 | 惯性滑行、吸附到格 | 每跨一格轻震、落定读数 |
| 完成任务 | 打勾 + 划掉 | 笔画有方向和速度 | 对勾描出、删除线、一次迸发 |
| 刷新数据 | 里程表 | 各位数字依次滚动，个位先动 | 新数字到位、旧数字滚走 |
| 复制 | 盖章 / 打钩 | 图标变形 | 对勾 + 播报 |
| 发送 | 纸飞机 / 气泡 | 向上、向远处飞出 | 飞出的同时输入框清空 |
| 收藏 | 心跳 | 先收缩再膨胀 | 实心化 + 少量粒子 |
| 上传 | 注水 | 液面随进度上升 | 百分比、满了冒泡 |
| 删除 | 碎纸机 / 揉纸 | 卷起、收缩 | 撤销按钮在原位停留 5s |
| 搜索 | 放大镜 / 展开 | 从图标长成输入框 | 结果高亮匹配的字 |
| 加入购物车 | 抛物线 | 小球沿弧线飞到购物车 | 角标数字弹一下 |

## 4. 同一个概念，不同定位

同一个「完成任务」放进四种定位（风格见 positioning.md）：

| 定位 | 怎么做 |
|---|---|
| 墨 Ink | 对勾像笔画一样描出，文字加删除线，没有迸发，calm 弹簧 |
| 夜航 Night | 对勾描出 + 一圈主色辉光，计数用 scramble 刷新 |
| 团子 Dango | 方框 bouncy 弹一下，彩纸迸开，旁边的小人跳一下 |
| 瓷 Porcelain | 对勾描出，卡片阴影轻轻收一下，几乎没有声音 |

## 5. 给自己的模板

拿到一句话的组件需求时，先填这张表，再写代码：

```
组件：
意图（用户想要的感觉）：
隐喻（现实里什么东西这样动）：
步骤与反馈：1 ___ → 2 ___ → 3 ___ → 4 ___
约束：尺寸 / 边界 / 并发 / 关闭方式 / 触屏 / 键盘 / 读屏 / 减少动态
惊喜（只一个）：
用户点名、不能改的部分：
可选方案（如果有）：
```
