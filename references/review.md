# 审查与交付

## 1. 一眼就像 AI 做的（反模式）

| 反模式 | 改成 |
|---|---|
| 默认紫蓝渐变 + 光晕（`#6366f1` 一类） | 从产品定位推色相（color.md） |
| 用 div 画假截图、假浏览器边框、假手机外壳 | 用真截图，或者不画 |
| 编造的精确数字（「47.2%」「10,000+ 用户」）、lorem ipsum | 真实数据；没有就明确标注「示例」 |
| 每个区块上方都有一行大写小标题 | 最多三分之一的区块用 |
| 三张一模一样的功能卡 | 卡片数量和形态跟内容走 |
| `transition: all` | 逐个写要过渡的属性 |
| 每个区块都淡入上移 | 只给值得强调的区块 |
| 什么都加玻璃 | 玻璃只给浮在内容上的东西 |
| emoji 当图标 | 一套图标库（icons-logos.md） |
| 圆角随手写（按钮 6、卡片 16、输入框 10） | `--r-control / --r-card / --r-panel` 三档 |
| 纯灰中性色 + 一个饱和蓝 | 中性色带一点色相 |
| 低对比灰字 | 次要文字也 ≥4.5:1 |
| 所有内容居中 | 正文左对齐；只有短标题和按钮可以居中 |
| 四五种字重、两套图标库混用 | 三档字重、一套图标 |
| 只有悬停才看得到的功能 | 触屏和键盘也能拿到 |
| `user-scalable=no` | 不禁止缩放 |
| 给 body 加 `overflow-x: hidden` 遮住溢出 | 找到溢出的元素修掉；必要时用 `clip` |
| 网格写裸 `1fr` | `minmax(0, 1fr)` |
| 生产力工具里自定义光标 | 用系统光标 |
| `z-index: 9999` | 用 `--z-*` token |
| `outline: none` 且没有替代 | `:focus-visible` 焦点环 |
| 文案堆「赋能」「一站式」「极致体验」 | 写这个产品具体做了什么 |

## 2. 自评打分（每项 1–5）

| 维度 | 5 分的样子 |
|---|---|
| 风格一致 | 换名测试不成立；所有 token 来自同一套推导 |
| 层级 | 3 秒内看得出这页最重要的是什么 |
| 色彩 | 主色克制；对比度报告全过 |
| 字体 | 最多两个家族；中文行高和行长正确 |
| 间距 | 4pt 网格；组内间距小于组间间距 |
| 反馈 | 每个可交互元素四拍齐全（feedback.md） |
| 动效 | 可打断、有物理感、减少动态有替代 |
| 特效 | 不超预算，搭配符合定位 |
| 多端 | 375 / 768 / 1280 都好看；触屏没有死角 |
| 可访问 | 键盘、读屏、对比度、焦点都过 |
| 细节 | 空、加载、错误都设计过；有一处记得住的细节 |

任何一项低于 3 分不交付；平均低于 4 分继续改。

## 3. 用 qa.py 检查

```bash
python scripts/qa.py http://localhost:8080/ --widths 360,375,768,1280 --out qa-out
python scripts/qa.py page.html --dark --reduce --tag dark
python scripts/qa.py http://localhost:8080/ --full --eval "document.querySelector('#menu').click()"
```

- 每个宽度检查：控制台错误和页面异常、失败的请求、超出视口的内容（被 body 裁掉的也算）、小点击区（触屏布局 <44px，鼠标布局 <24px；用 `::before` 撑大的点击区算数）、小于 11px 的可见文字、没有 alt 的图片、没有名字的控件、加载失败的字体。
- 宽度小于 1024 按触屏设备跑（粗指针、无悬停），只靠悬停的界面会暴露出来。
- 截图和 report.json 写进 `--out` 文件夹；`--tag v2` 给截图和报告的文件名加前缀（`v2-390.png`、`v2-report.json`；加了 `--dark` 的截图名还会带 `-dark` 后缀），几次运行不会互相覆盖。
- `--wait` 默认 1200ms。页面有入场动画、粒子或 webfont 时调到 3000–4000，否则截图可能拍到动画中途。
- **退出码 1** = 有错误、失败请求或溢出。**退出码 0 不代表点击区和字号合格**，要读输出里的 `target`、`tiny`、`unnamed` 行。
- 安装：`pip install playwright && python -m playwright install chromium`。装不了内置 Chromium 时，脚本会自动改用本机的 Chrome 或 Edge。
- 本地文件可以直接传路径；页面用了 `fetch` 或 ES module 时先起本地服务器（`python -m http.server 8080`）。

流程：跑 → 每个宽度的截图都看（深色也看）→ 改 → 再跑，直到 FAIL 和小点击区都清零。

### 截图里的已知假象（不是页面的问题）
- 整页截图（`--full`）里，sticky 和 fixed 元素可能出现在图片中间或重复出现。
- 整页截图、或者比视口高的元素截图之后，Playwright 会关掉触屏模拟。qa.py 已经先检查再截图；自己写脚本时也要注意这个顺序。
- 触屏模拟下 CDP 的 `Input.synthesizeScrollGesture` 不会滚动页面，测试触摸滚动要用 `Input.dispatchTouchEvent`。

## 4. 脚本查不到的，要手动看

- 只用键盘走一遍：Tab 顺序、焦点可见、Esc 关闭浮层、手势有按键替代。
- 读屏抽查一个完整流程（VoiceOver、NVDA 或 TalkBack）。
- 系统打开「减少动态」再看一遍。
- 真机触屏：至少一台手机，试点按、拖动、长按、横屏。
- 慢网络（DevTools 节流）：骨架屏、加载态、按钮不会被重复提交。
- 极端内容：很长的名字、很长的英文单词、空列表、上万条数据、0 和负数。
- 浏览器缩放到 200%；Windows 高对比度模式。

## 5. 交付清单

1. 简报和假设（positioning.md 第 1 节）
2. 旋钮值和推导理由（positioning.md 第 7 节的格式）
3. tokens：palette.mjs 的输出和对比度报告
4. 组件和状态：每个组件的四拍
5. 动效说明表（motion.md 第 10 节）
6. 多端说明：哪些组件在哪个宽度、哪种输入方式下换形态
7. qa.py 结果（每个宽度一行）和截图位置
8. 已知限制和没验证的部分，比如「没在真机上测」「没跑读屏」
9. 外部代码、图标、字体的出处和授权（sources.md 的模板）

**如实报告**：没跑的检查写「没跑」；失败的写失败和原因；不要把「应该没问题」写成「已验证」。
